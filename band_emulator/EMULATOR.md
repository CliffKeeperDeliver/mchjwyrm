# Основа эмулятора Band 9

Для работы с ядром используйте **`debug_band_emulator.bat`** и
[инструкцию отладчика](DEBUGGER.md): добавлены шаги, точки останова,
сохранение/восстановление состояния и продолжение после аппаратной зависимости.
Ниже описан сохранённый режим одноразового выполнения отдельных функций.

Рабочая основа для **изолированного выполнения ARM-функций** из настоящей
прошивки Band 9 Global 2.3.98. Использует Unicorn 2.1.4, модель Cortex-M33,
Thumb/M-profile и Capstone 5.0.9 для журнала инструкций.

Это консольный инструмент. Экран, сенсор, Bluetooth, датчики,
доставка прерываний и полноценная загрузка NuttX пока не реализованы.
В отладчике доступны ограниченные таймеры с виртуальным тактом инструкций.
Никакого подключения к браслету для запуска не требуется.

Теперь доступен отдельный [погодный сценарий](WEATHER.md):
`run_weather_emulator.bat --a -3 --b 3` из корня проекта. Он выполняет
оригинальные функции температур без аппаратных заглушек.

## Быстрый запуск

Из корня проекта:

```powershell
.\run_band_emulator.bat
```

По умолчанию запускается демонстрация с настоящей функцией прошивки.
Отчёт сохраняется в `band_emulator/results/last-run.json`.
Готовый проверенный результат также находится в `results/demo.json`.

Ожидаемый результат:

```text
returned: 6 instructions; PC=0x10000000
Real firmware function / modeled register:
expected=0xa5a5a5a2, actual=0xa5a5a5a2, passed=True
```

Если Python-зависимости отсутствуют:

```powershell
python -m pip install --target band_emulator/python_deps -r band_emulator/requirements.txt
```

Зависимости установлены локально в папку исследования.

## Что именно выполняется в демонстрации

Берутся исходные байты `vela_ap.bin` со смещения `0x12cc`.
Вызов этой функции найден в стартовом коде по смещению `0x14`.
Функция состоит из шести инструкций:

```asm
ldr r2, [pc, #0xc]       ; литерал содержит 0x40080000
ldr r3, [r2, #0x5c]
bic r3, r3, #7
orr r3, r3, #2
str r3, [r2, #0x5c]
bx lr
```

Регистр `0x4008005c` заменён **явной моделью одного 32-битного значения**.
Проверяем, что три младших бита становятся равны 2, а остальные сохраняются.
Назначение этого аппаратного регистра и его побочные эффекты не подтверждены;
такая модель проверяет вычисление, а не корректность настройки реального чипа.
Это служебная функция запуска, не функция погоды.

## Запуск с начала образа

```powershell
.\run_band_emulator.bat --startup --output band_emulator/results/startup.json
```

Ожидаемая остановка — `memory_fault` на чтении `0x4008005c`, PC `0x0c1012ce`.
В этом режиме регистр автоматически не подставляется. Код возврата 2
означает, что выполнение не дошло до контролируемого возврата функции.

Следующий эксперимент с явно заданной моделью:

```powershell
.\run_band_emulator.bat --startup --mmio-register 0x4008005c=0 --output band_emulator/results/startup-one-register.json
```

Это разрешает только данный 32-битный регистр. Другие адреса даже в той же
странице останавливают опыт. Каждый последующий аппаратный блок необходимо
исследовать отдельно, а не заменять все неизвестные чтения нулями.

## Произвольная функция

```powershell
.\run_band_emulator.bat --entry-offset 0x12cc --mmio-register 0x4008005c=0xffffffff --register r0=0 --max-instructions 1000 --timeout-ms 2000 --output band_emulator/results/function.json
```

`--entry-offset` — чётное **смещение в файле** `vela_ap.bin`.
Thumb-бит добавляется инструментом. Имена входных регистров: `r0`–`r12`,
`sp`, `lr`. По умолчанию LR ведёт на отдельную точку остановки.
Переопределение LR может помешать нормальному завершению опыта.
Все новые экземпляры CPU получают свежую память; один экземпляр запускается один раз.

Для функций с буферами есть Python API `write_ram` / `read_ram`:

```python
from pathlib import Path
from emulator import Emulator, load_profile

root = Path('band_emulator')  # при запуске из корня проекта
profile = load_profile(root / 'profiles/n66gl_2.3.98.json')
emu = Emulator(profile)
emu.write_ram(0x20001000, b'input\x00')
# result = emu.run(known_function_offset, {'r0': 0x20001000})
# output = emu.read_ram(0x20001000, 6)
```

При использовании API добавьте `band_emulator` в `sys.path` или запускайте
свой скрипт из этой папки; путь профиля выбирайте соответственно.
Параметры и адрес функции нужно определить анализом, приведённый буфер —
только пример подготовки памяти.

## Модель памяти и ограничения

- Образ отображается в `0x0c100000` с правами чтения и выполнения. База
  выведена из перехода через литерал `0x0c100015` по смещению `0x64`.
- RAM: `0x20000000`–`0x2015ffff`, изначально нулевая, чтение/запись.
  Эта область — рабочее предположение, а не полностью проверенная карта чипа.
- SP: `0x2015fe80`, значение из литерала старта по смещению `0x68`.
- Контролируемый возврат: `0x10000000`; это адрес стенда, не браслета.
- Исполнение разрешено только внутри байтов основного образа. Добавлено
  зеркало для чтения по `0x2c100000`; исполнение из него запрещено.
  Код, скопированный в RAM, и ROM-подпрограммы пока не поддерживаются.
- Нет обработки SVC, аппаратных прерываний, Secure/Non-secure взаимодействий
  и полноценной модели загрузки. Выбор CPU M33 не моделирует весь BES SoC.
- Неизвестная память, неподдерживаемые исключения и регистры завершают опыт
  с ошибкой. При ошибке промежуточные регистры CPU не считаются результатом функции.
- Лимиты инструкций и времени защищают от зависания. Трасса хранит последние
  128 инструкций, события MMIO — последние 256. Полные счётчики идут отдельно.
  Счётчик инструкций учитывает инструкции, допущенные к выполнению, включая
  ту, на которой произошло исключение или ошибка доступа.
- SHA-256 образа проверяется перед запуском. Для другой версии или изменённого
  образа нужен отдельный профиль и перепроверенные смещения.

Статусы: `returned`, `memory_fault`, `unmodeled_register`,
`unsupported_execution`, `unsupported_exception`, `instruction_limit`,
`timeout`, `cpu_error`, `stopped`. Только `returned` означает достижение
контролируемого возврата; в демонстрации дополнительно проверяется значение.
Даже `returned` не подтверждает корректность работы на реальном устройстве.
Коды выхода CLI: 0 — контролируемый возврат/успешная демонстрация,
2 — незавершённое выполнение, 1 — ошибка настройки или загрузки.

## Проверено 7 ноября 2026

```powershell
python -m unittest discover -s band_emulator/tests -v
```

67 тестов прошли, включая отладчик, SCB/NVIC, кэш, AON, IOMUX/CMU, таймеры и зеркало RAM.
Базовая функция проверена на 32 значениях регистра;
добавлены 74 вызова погодных функций, описанные в `WEATHER.md`.
Проверена остановка настоящего стартового кода на первом неизвестном чтении.
Синтетические короткие Thumb-программы отдельно проверяют лимиты времени и
инструкций, запрет записи во flash и исполнения из RAM, передачу буферов,
исключения и запрет выполнения выравнивающего заполнения после конца образа.
Синтетические проверки не выдаются за тестирование функций прошивки.

Функции выбора температур и их перевода сохранены как отдельный сценарий.
Отладчик со сценарием `scripts/startup-io.debug` проходит настройку
системного блока, обоих кэшей, IOMUX/CMU, обоих таймеров и исполняет код из RAM:
85 925 / 85 926 инструкций до чтения BOOTMODE `0x40080038` для двух явно
заданных экспериментальных ревизий 13 / 14. Это не измеренные ревизии браслета.
Исполнение из зеркала RAM — отдельная опция отладчика; ограничения базового
одноразового стенда выше сохранены. Физические частоты таймеров, прерывания и следующие зависимости
загрузки ещё предстоит реализовать. Полный интерфейс устройства пока не запускается.
