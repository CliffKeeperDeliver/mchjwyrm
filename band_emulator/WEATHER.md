# Погодные функции в эмуляторе

## Запуск

Из корня проекта:

```powershell
.\run_weather_emulator.bat --a -3 --b 3
.\run_weather_emulator.bat --a 20 --b 10 --units C
.\run_weather_emulator.bat --fallback-mode --fallback -2
```

Первый пример возвращает −3 / 3 °C и 27 / 37 °F. Второй сортирует значения
в 10 / 20 °C. В третьем обе функции используют резервное поле −2 °C (28 °F).
Результаты и трассы записываются в `results/weather.json`; можно задать
отдельное имя через `--output`.

## Что выполняется

Функции работают с контролируемой структурой в RAM. Вызовы библиотечных
функций не подменяются, MMIO не используется. Исходный файл проверяется по
SHA-256; байты прошивки не изменены.

| Файловое смещение | Наблюдаемое поведение |
| --- | --- |
| `0x22d834` | При ненулевом поле `+0x17c` выбирает меньшее из двух signed16 полей `+0x182` и `+0x184` |
| `0x22d85e` | При ненулевом поле `+0x17c` выбирает большее из тех же полей |
| Оба селектора | При нулевом `+0x17c` используют signed16 поле `+0xca` |
| `0x22d790` | При нулевом флаге возвращает температуру без изменения; при ненулевом выполняет `9*C/5+32` с собственным округлением |
| `0x3db100` | Обёртка перевода резервного значения с приведением к signed16 |

Флаг единиц находится по адресу `0x20097320`. Его адрес получен из литерала
и инструкции `ldrb`, а в опыте он задаётся явно. Буфер по адресу `0x20001000`
выбран для стенда; это не адрес реальной погодной структуры браслета.

Связь с погодным кодом подтверждается вызывающей функцией по смещению
`0x224a4c`: она ссылается на диагностическую строку
`app_weather_get_local_temperature` и вызывает оба селектора.
Строка находится по смещению `0x540adc`; её адрес `0x2c640adc`
записан в пуле литералов по `0x224b54`.

Исследовательские названия `minimum` / `maximum` описывают подтверждённое
поведение, а не восстановленные имена символов. Семантика `+0x17c` как
счётчика/флага пока не установлена; в сценарии используются значения 0 и 1.
Это не определяет временной интервал прогноза и не доказывает, что экран
показывает именно эти поля в каждой ситуации.

## Особенность округления °F

Сохранено фактическое поведение оригинального кода: например, −40 °C
возвращает **−39 °F**, а −30 °C — **−21 °F**. Анализ инструкций указывает
на добавление `+0.5` перед усечением к нулю, что даёт такой результат для
отрицательных чисел. В эмуляторе это не исправлялось. Проверка именно
отображения этих случаев на физическом браслете не выполнялась.

## Проверка и воспроизводимые материалы

```powershell
python band_emulator/weather_evidence.py
python -m unittest discover -s band_emulator/tests -v
```

- `results/weather-evidence.json` — ссылка на строку, адреса и инструкции.
- `results/weather-functions.thumb.txt` — пять диапазонов дизассемблирования
  без интерпретации таблиц и литералов как инструкций.
- `results/weather.json` — реальные результаты выполнения четырёх сценариев.
- `tests/test_weather.py` — 60 запусков селекторов °C на 30 парах значений,
  8 запусков известных точек °F, 2 отрицательных случая и 4 проверки
  резервного поля; отдельно проверяются границы ширины входных значений.

Всего в проекте прошли 18 тестов. Новые погодные проверки выполняют 74
вызова настоящих функций прошивки без заглушек. Экран и вся ОС по-прежнему
не эмулируются; следующий шаг — исследование форматирования и ресурсов UI.
