# GPIO, ADC, NOR и следующая граница

Наблюдения относятся только к stock Global 2.3.98 и SHA-256 из `BOOT.md`.
Основание — дизассемблирование локального образа, не документация точной платы.
Новые модели не доказывают совпадение физических reset values.

## Исполняемый путь

- `0x0c1406a4`: настройка GPIO завершена.
- `0x0c39a1c0`: регистрирует `/dev/adc_batt_voltage`, `/dev/adc_temp_shell`,
  `/dev/adc_hw_version`; читает канал 4 через `0x0c39a098`.
- Таблица `0x2c66b1dc`: шесть записей `<HHBB>`, границы/ревизия:
  0–100 → 0, 150–300 → 1, 301–500 → 2, 500–700 → 4,
  701–900 → 3, 901–1100 → 5. Порядок сравнения на общей границе 500
  определяет оригинальный код. Результат лежит в `0x200af50c`.
- `0x0c51ac82`: устройства АЦП зарегистрированы, вызывается финальная подготовка платы.
- `0x0c51a8dc`: геометрия flash проверена, далее `0x0c16a1fc` регистрирует разделы.
- `0x0c51a964`: возврат из регистрации разделов. CLI `--until storage`.
- `0x0c510390`: начало инициализации Bluetooth-драйвера.
- `0x0c50db00`: строка `btdrv_common_init`, запрос ревизии через `0x0c100370`.
- `0x0c51ac86` (полный возврат из настройки платы) **пока не достигнут**.

## GPIO

Таблица баз `0x2c70096c`: `0x40081000`, `0x40089000`, `0x4008a000`.
Штатные функции: направление `0x0c5161a4`, set `0x0c516210`,
clear `0x0c516270`, read `0x0c5162f4`; банк по номеру /32.
Выводы 80/81 идут в отдельный аппаратный путь и не моделируются.
Wake-конфигурация: `0x40085080/84/88`, наблюдаемая настройка pin46.
GPIO-модель в `gpio_control.py` хранит set/clear и IRQ-состояние, IRQ44.
Вход в оригинальный обработчик проверен, полный возврат после обслуживания — нет.
Семантика status 0x40/0x44 пока предположительная masked/raw; отсутствуют
физические подтяжки, маршрутизация IOMUX и задержки debounce.

## Виртуальная геометрия и заводской сектор

Описание HAL flash0: `0x20066c18`, stride24. +0 initialized, +1..3 JEDEC,
+8 capacity, +12 page size, +16 flags. Функция `0x0025cc14` возвращает
сектор 4096 или 8192 и блок 32768 или 65536 в зависимости от flag8.
`chip/bes_flash.c` в `0x0c16a354..0x0c16a378` требует страницу 512 и сектор8192.
HLE задаёт capacity8MiB/page512/flag8; JEDEC неизвестен (ноль).
Успешный возврат регистрации не доказывает доступность содержимого всех разделов.

Заводской сектор `0x287fe000` синтетически стёрт (8192 байта 0xff), RO.
Функции `0x0c505864` и `0x0c50576c` проверяют magic0xba80 и сами выбирают
ветку отсутствия данных. Остальные неизвестные flash-области не добавлены.
Это не физический дамп, не подлинная калибровка и не полный NOR-контроллер.

## Частоты

Арбитр запросов `0x00260e88` исполняется штатно; клиенты0..42, профили0..7.
HLE заменяет аппаратные листья: getter `0x00264fea`, setter `0x0025ecd0`,
подготовку питания `0x00264e58`, переходы `0x0025eecc/0x0025eeac`.
Начальный виртуальный профиль3. Реальные Hz и аналоговое питание не моделируются.
Конфигурация CMU60/64 остаётся неподдерживаемой для прямого доступа.

## Следующий шаг: внутренний SPI

`0x0c100370` читает регистр0x3000 в 16-битный буфер через veneer
`0x0c1017f0` → `0x00260230`. Драйвер выделяет поля адреса, выбирает
устройство и вызывает `0x00260bbc` → `0x002603cc` → `0x0026038c`.
Текущая остановка: PC `0x0026039e`, запись0 в `0x40009000`.
Для продолжения нужна модель внутреннего SPI/регистров подключённого чипа,
либо узкий документированный HLE-контракт; нельзя выдавать произвольные нули
за ответы всей шины. Bluetooth, экран и полная загрузка приложения пока отсутствуют.

**Выполнено 9 ноября 2026** (подробности — `BOOT.md`, «Шаг 2»). Причина остановки:
`ispi_ctrl` (`0x20068674`) был нулевым, потому что `hal_analogif_open`
(`0x0c101564`) входит в заменённую раннюю подготовку `0x0c10170a`. Теперь она
исполняется штатно с моделью `ispi_control.py`, CHIP_ID PMU `0x153` проверен
прошивкой, запуск BT-контроллера `0x0c510390` заменён. Следующая остановка —
`0x40160404` из `0x002614a2`.

SRAM-код имеет два разных соответствия файлу:

- `0x0025c1c0..0x00266c18` → file `0x19a4..0xc3fc`;
- `0x00268700..0x0026ad38` → file `0xc3fc..0xea34`.

Не применять формулу первого диапазона ко второму. Полные RAM-алиасы —
те же адреса +`0x1fe00000`. Не устанавливать общий hook записи памяти:
ошибка Unicorn ITSTATE описана в `BOOT.md`.
