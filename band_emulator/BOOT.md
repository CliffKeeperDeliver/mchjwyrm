# Запуск ОС Band 9 на ПК

Новый основной запуск — **`boot_band_emulator.bat`** в корне проекта.
Открывается [браузерный интерфейс](BROWSER.md) управления оригинальной прошивкой
**2.3.98 Global**. Прежнее настольное окно: `boot_band_emulator.bat --desktop`.
Нажать **«Запуск»**. Телефон и браслет не требуются.

## Что достигнуто

Исполняются стартовый код, перенос данных, C runtime, инициализация ядра,
создание пользовательской и системной куч, регистрация системных устройств,
создание задач и переключение контекста. В памяти ОС обнаруживаются:

| PID | Задача |
| --- | --- |
| 0 | `Idle_Task` |
| 1 | `hpwork` |
| 2 | `lpwork` |
| 3 | `AppBringUp` |

Прошивка сама выводит `system power on....`. Её обработчик SVC сохраняет
контекст и передаёт управление через `0x0c140fcc` в `AppBringUp`
(`0x0c1404e8`). Проверен также вход и возврат из обработчика IRQ 46
(номер исключения 62). Имена задач считываются из таблицы PID в гостевой RAM,
а не задаются интерфейсом эмулятора.

Теперь проходят настройка GPIO, регистрация устройств АЦП, выбор виртуальной
ревизии платы, проверка геометрии флеш-памяти и регистрация разделов накопителя.
Затем начинается штатный драйвер Bluetooth (`btdrv_common_init`).
Текущая граница полного прогона: запись SPI в **`0x40009000`** из
`0x0026039e`, при попытке прочитать идентификатор чипа через регистр `0x3000`.
Это около **1,86 млн ARM-инструкций**. На неизвестном оборудовании выполнение останавливается.
Дисплей, Bluetooth, датчики и полная загрузка приложения ещё не работают.
Окно программы показывает состояние эмулятора; изображения экрана часов пока нет.

## Управление

Ниже описано прежнее настольное окно. Расширенное управление из браузера,
сеть, именованные снимки и редактор RAM описаны в [BROWSER.md](BROWSER.md).

- **Запуск / Пауза / Шаг** — выполнение гостевого кода. Шаг считает допущенную
  ARM-инструкцию; перед ней могут обслуживаться аппаратные замены/исключения.
- **Сброс** — новый процессор и чистая память из исходного образа.
- **Сохранить / Восстановить** — один пользовательский снимок в памяти процесса.
  Включает CPU/FPU, SRAM, обе проекции PSRAM, таймеры, прерывания, журнал и HLE.
  Входы GPIO/АЦП и виртуальные частотные профили также восстанавливаются.
  Закрытие окна уничтожает снимок. Кнопка сохранения сначала ставит выполнение на паузу.
- **Точка останова** — адрес Thumb-инструкции без младшего бита. Предложенный
  `0x0c1404e8` останавливает перед первой инструкцией `AppBringUp`.
  Следующее нажатие запуска проходит эту точку один раз.
- **Отчёт** — `results/boot-ui.json`. Это диагностический JSON, не снимок CPU.
- **Входы платы** — задать GPIO 0–79 и уровень 0/1 либо канал АЦП и значение
  0–65535. Команда ставит исполнение на паузу. GPIO 46 штатный код настраивает
  на спадающий фронт: после настройки задать 1, затем 0, затем продолжить.
  Это номер вывода, не подтверждённое назначение кнопки браслета.
  АЦП 4 по умолчанию равен 600: штатная таблица выбирает ревизию платы 4.
  Для другой ревизии менять значение **до** инициализации АЦП, например до
  `AppBringUp`. Изменение после чтения не переписывает уже выбранную ревизию.

После аппаратной ошибки состояние может быть частично изменено. Продолжение
запрещено до сброса или восстановления снимка. Для точного отката отдельной
инструкции остаётся прежний `debug_band_emulator.bat`.

Консольный запуск из корня:

```powershell
.\boot_band_emulator.bat --cli --until bringup
.\boot_band_emulator.bat --cli --until storage
.\boot_band_emulator.bat --cli
python band_emulator/boot_machine.py --until storage --adc 4=720 --gpio 46=1
```

`--until bringup` останавливается перед `AppBringUp`, `--until storage` — после
регистрации разделов (`0x0c51a964`); оба возвращают код 0 при достижении точки.
Без `--until` выполняется до следующей аппаратной зависимости
или установленного лимита; диагностическая остановка возвращает код 2.
Отчёт по умолчанию — `band_emulator/results/boot-machine.json`.
Прямой Python-вход поддерживает `--seconds`, `--instructions`, `--report`.
Параметры `--adc CHANNEL=VALUE` и `--gpio PIN=LEVEL` можно повторять.

## Как устроен новый режим

`boot_machine.py` выполняет оригинальные инструкции через Unicorn Cortex-M33.
Образ на диске не изменяется. Адреса HLE привязаны к SHA-256
`7c0115d92f7aa5d22dcb3f9a1ff0614904d736609d2d29eebc32f9ab3f7ebab1`
и конкретной карте памяти. Это экспериментальная загрузка с высокоуровневыми
заменами аппаратных служб, **не точная эмуляция всей платы**.

Новые компоненты:

- 16 MiB внешней RAM с общим буфером у `0x38000000` и `0x3c000000`.
  Размер выбран по верхней границе кучи `0x3cff0000` в штатном коде.
- Ускорение трёх фактически используемых циклов копирования/обнуления PSRAM.
  Копируется 179264 байта, обнуляется 7 MiB. Завершающие сравнения исполняются
  процессором. Ускоренные итерации **не включаются** в счётчик ARM-инструкций.
- Однократный 32-битный таймер второго канала `0x40084020`, IRQ 46;
  SysTick и учёт PRIMASK/BASEPRI/FAULTMASK при доставке.
- Вход через штатную таблицу векторов; базовые и расширенные FP-кадры,
  MSP/PSP, выравнивание стека, исполнение штатного обработчика и возврат.
  Возврат перехватывается на `bx lr` общего обработчика этой сборки.
- Снимки всей машины и таблица задач ОС.
- GPIO: три банка, 80 выводов, атомарные set/clear, направление, вход/выход,
  фронтовые/уровневые IRQ, маски и подтверждение. IRQ 44 доставляется в
  оригинальный обработчик. Debounce и wake сохраняют только конфигурацию.
- Виртуальная геометрия NOR: 8 MiB, страницы 512, секторы 8192 байта.
  Штатные функции запросов геометрии и регистрации разделов исполняются.
  JEDEC неизвестен и оставлен нулевым; доступного полного образа flash нет.
- `0x287fe000..0x287fffff`: явно стёртый виртуальный заводской сектор (`0xff`),
  только чтение. Прошивка сама отвергает его заголовок и выбирает ветку отсутствия
  заводских данных. Калибровка и MAC-адреса настоящего браслета здесь отсутствуют.
- Штатный assert останавливает машину со строкой, исходным файлом и адресом
  вызова вместо бесконечного исполнения диагностического цикла.

Для скорости режим не делает полный снимок CPU перед каждой инструкцией.
Сохраняются последние 64 адреса трассы; дизассемблирование выполняется при
формировании отчёта.

## Явные аппаратные замены

Все вызовы записываются в `hle_replacements`. Имена ниже описывают назначение,
восстановленное по вызывающему коду; отладочные символы производителя отсутствуют.

| Адрес | Замена |
| --- | --- |
| `0x0c10170a` | Ранняя подготовка платы; задаются экспериментальные состояния таймеров и CMU |
| `0x00261bf4` | Аппаратная подготовка PSRAM; память предоставляет хост |
| `0x0c519bdc` | Инициализация отладочного UART |
| `0x0c519bf4`, `0x002620f8` | Перехват готового текстового буфера в журнал |
| `0x0025fd10`, `0x0025fe90` | Аппаратная настройка IOMUX/маршрутов выводов |
| `0x0c51a81c` | Ранняя инициализация платы; флаг готовности и виртуальное описание NOR в RAM |
| `0x0c165074` | Подготовка отладочного счётчика циклов |
| `0x00262a80` | RTC: фиксированное начальное календарное значение 2026-01-01 |
| `0x0c519cd4`, `0x0c519c64`, `0x0c519c98` | Остановка, перезагрузка, включение watchdog; физический сброс не моделируется |
| `0x0c101610` | Причина загрузки: экспериментальное нулевое значение |
| `0x0c39a098` | Чтение явно заданного входа АЦП; неизвестный канал останавливает машину |
| `0x00264fea`, `0x0025ecd0` | Чтение/изменение виртуального частотного профиля 0–7 |
| `0x00264e58`, `0x0025eecc`, `0x0025eeac` | Профиль питания и запись запросов перехода; без аналоговых эффектов |

Частотный профиль по умолчанию — 3. Это экспериментальный enum, а не измеренные
герцы. Штатный арбитр запросов разных клиентов (`0x00260e88`) выполняется без
замены; заменены его аппаратные операции. Частота исполнения и виртуальных
таймеров от этих профилей не меняется. Значения АЦП, геометрия NOR и пустой
заводской сектор — явные условия виртуальной платы, не дамп пользовательских часов.

Системный аллокатор, планировщик, создание задач и SVC-диспетчер не заменяются
успешными ответами: их код исполняется из прошивки.

## Ограничения модели

Такт таймеров — допущенная инструкция, а не физическое время. Внешний такт
SysTick — раз в 1024 инструкции, чтобы короткий аппаратный период не вызывал
непрерывный вход в обработчик. Это явно заданная HLE-модель частот.
Поддерживается один домен безопасности, без вложенных прерываний, MPU,
эскалации fault, ленивого сохранения FP и аппаратного watchdog.
Неподдерживаемые варианты исключения останавливают исполнение.

В Unicorn 2.1.4 [известна ошибка ITSTATE в обработчиках обращений к памяти](https://github.com/unicorn-engine/unicorn/issues/2309).
Новый режим ограничивает обработчики записи двумя перенесёнными участками
кода SRAM, не инструментируя обычные записи в стек/кучу. Исполнение произвольных
участков SRAM вне этих двух областей запрещено. Изменение исполняемого кода
во время условной инструкции остаётся отдельным неподтверждённым сценарием.

Базовая структура кадров сверена с кодом штатного обработчика и
[описанием исключений Armv8-M](https://community.arm.com/cfs-file/__key/communityserver-discussions-components-files/471/armv8_2D00_m_5F00_exception_5F00_model_5F00_user_5F00_guide_5F00_107706_5F00_0100_5F00_01_5F00_en.pdf).
Достижение `AppBringUp` не доказывает, что изменённая прошивка безопасна для
записи в настоящий браслет.

## Проверки

Пройдено **87 тестов**, журнал — `results/test-run-board.txt`.
Проверены создание окна и один шаг, а также полный путь через его обработчик
команд: GPIO/АЦП → снимок → изменение → восстановление → сброс → регистрация
разделов → снимок → SPI-зависимость → восстановление точки останова.
Отчёт прогона обработчика окна — `results/boot-ui-board.json`.
Предыдущие журналы `test-run-boot.txt`, `test-boot-final.txt` и
`boot-ui-worker.json` оставлены как история прежней границы на GPIO.

```powershell
python -m unittest discover -s band_emulator/tests -v
python band_emulator/boot_ui.py --smoke-test
```

Новый интеграционный тест выполняет штатный старт до `AppBringUp`, проверяет
четыре задачи, сообщение консоли, заполнение кучи и сохранение кода SRAM.
Затем сохраняет всю машину, повторяет 120000 инструкций после восстановления
и сравнивает регистры, события, таймер, задачи и хеш PSRAM. После настройки
GPIO проверяет вход в оригинальный обработчик IRQ 44 от заданного фронта,
восстанавливает снимок и идёт через регистрацию разделов до SPI-зависимости.
Полное обслуживание IRQ 44 до возврата здесь пока не проверяется.
Отдельно выполняются штатные ARM-функции установки направления, записи и
чтения GPIO на выводах 0, 31, 46, 79, а также штатный арбитр частотных запросов:
при снятии более высокого запроса сохраняется запрос другого клиента.
