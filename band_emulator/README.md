# Исследование прошивки Xiaomi Smart Band 9

Основной запуск: **`boot_band_emulator.bat`** из корня проекта.
[Браузерный интерфейс](BROWSER.md) — основной: компьютер исполняет ARM-код,
несколько браузеров управляют общей машиной через локальную сеть или VPN.
Прежнее окно запускается с `--desktop`, консоль — с `--cli`.

[Режим загрузки ОС и окно управления](BOOT.md) выполняет штатный код ядра,
создаёт четыре системные задачи и входит в `AppBringUp` через штатный
обработчик SVC. Работают экспериментальная PSRAM, кадры исключений,
таймерный IRQ и снимки всей машины. Подготовка оборудования частично заменена
явными HLE-службами. Пройдены GPIO, АЦП, регистрация разделов, внутренний SPI
и PMU; инициализация платы завершается, Bluetooth-контроллер отсутствует.
Текущая остановка — `0x40160404`. Дисплей пока отсутствует.
В окне доступны виртуальные входы GPIO/АЦП, включённые в снимки машины.

Строгий режим: **`debug_band_emulator.bat`**.
[Отладчик ядра](DEBUGGER.md) выполняет настоящий старт прошивки, поддерживает
шаги, точки останова, память/регистры, сохранение состояния и продолжение.
С экспериментальными моделями проверены настройка системного блока,
кэшей и выполнение кода, перенесённого прошивкой в RAM. Старт доходит
через настройку IOMUX/CMU и запуск обоих виртуальных таймеров до BOOTMODE
(`0x40080038`), полный запуск ОС ещё не реализован.

Последний сценарий: `debug_band_emulator.bat --script band_emulator/scripts/startup-io.debug`.
Он проверяет обе ветки условия ревизии чипа; фактическая ревизия браслета
пока не установлена. Этот строгий режим покрывался 67 тестами; вместе с новым
HLE-режимом результаты проверок приведены в [BOOT.md](BOOT.md). Частоты таймеров экспериментальные:
один входной тик на инструкцию, без реальных таймингов чипа.

[Погодный сценарий](WEATHER.md) сохранён как отдельный эксперимент с функциями.

Общая инструкция стенда: [EMULATOR.md](EMULATOR.md).
Исходный образ и инвентаризация находятся в `n66gl-2.3.98/`,
исполняемые сценарии — в Python-файлах этой папки, отчёты — в `results/`,
проверки — в `tests/`, сторонние библиотеки — в `python_deps/`.

## Результат первого этапа — 7 ноября 2026

Получен и разобран полный пакет обновления **2.3.98 Global**, модель
**miwear.watch.n66gl**. Наличие этой версии на пользовательском браслете
подтверждено сохранённым журналом Mi Fitness от **17 сентября 2026**.
**Текущая версия 2.3.98 подтверждена 7 ноября 2026** через ADB по Wi-Fi:
Mi Fitness → Устройство → Еще → Версия устройства. На странице устройства
браслет обозначен как Xiaomi Smart Band 9 со статусом «Подключено».
Версия совпадает с `sw_version` скачанного OTA. Свидетельство записано в
`n66gl-2.3.98/device-version-verification.json`.

Источник: поле `fullPackageUrl` в локальном
`../mi_fitness/backup/external_data/files/log/XiaomiFit.main.log`.
Подписанная ссылка сработала через curl; её параметры не сохранены в отчёте.
Открытая ссылка без параметров вернула 403.

Файл: `n66gl-2.3.98/stock-2.3.98.bin`, 43 410 024 байта.
MD5 совпал со значением из журнала: `feff6a92d0d6c78226e376555475cd0d`.
SHA-256: `08dc79298923afc8e8c29690f86a36054283a7862253268059e7302c115663a0`.
Происхождение записано в `provenance.json`. Сопоставление MD5 не заменяет
проверку подписи изготовителя; криптографическая подпись отдельно не проверялась.

## Структура

Несмотря на расширение `.bin`, внешний пакет — обычный ZIP.
В `ota.json` указаны `magic_string=n66`, `sw_version=2.3.98`,
`firmware_type=all`, для разделов — `update_way=all`.
Это полный OTA-пакет согласно манифесту, **не полный дамп флеш-памяти браслета**.

| Компонент | Размер, байт | Что установлено |
| --- | ---: | --- |
| `vela_ap.bin` | 6 498 804 | Основной образ; читаемые строки и ARM Thumb-код |
| `vela_ota.bin` | 657 792 | В манифесте обозначен `main_bootloader` |
| `app.bin` | 22 448 128 | ROMFS, включая 187 файлов ресурсов `/weather/` |
| Остальные 8 ROMFS-образов | См. `inventory.json` | Локализации, шрифты, системные ресурсы, циферблаты и др. |
| `ota.json`, `version` | 3457 и 18 | Манифест и версия ресурсов |

Внешний ZIP содержит 13 файлов. CRC всех записей проверен при чтении.
MD5 всех 12 компонентов совпадает с манифестом.
Проверены контрольные суммы заголовков всех 9 ROMFS-образов.
Их каталоги содержат в сумме 5509 записей. Файлов, начинающихся с ELF,
в перечисленных файловых системах не обнаружено.

## Доступность кода

В `vela_ap.bin` с файлового смещения `0x10` получен согласованный фрагмент
ARM Thumb/M-profile: переход, установка MSP/MSPLIM, барьер ISB,
циклы копирования и обнуления памяти. Результат — `startup.thumb.txt`.
Адреса в этом файле — **смещения в файле**, а не подтверждённые адреса исполнения.

Образ содержит читаемые пути исходников NuttX и строки погодных функций.
В `weather-index.json` сохранены 259 строк, содержащих `weather`, и 187
записей ресурсов погоды. Например, найдены `app_weather_get_local_temperature`,
`weather_async_work`, путь `/data/app/weather/database.db`.
Строка с именем функции сама по себе не определяет адрес её кода.

Вывод: внешней шифровки, мешающей доступу к исследованному коду и ресурсам,
нет. Статический анализ возможен. Это **не доказательство**, что любая часть
пакета незашифрована, что модификацию примет браслет или что она загрузится.

## Что ещё не сделано

- Не восстановлена полная карта памяти, ROM-функций и устройств. Добавлено зеркало образа для чтения `0x2c100000`.
- Не исследованы все зависимости погодного интерфейса и связь полей с временными интервалами.
- Эмулятор целого браслета не создан; способ аппаратного восстановления не проверен.
- Ничего не передавалось и не прошивалось на браслет.

## Основа эмулятора — 7 ноября 2026

Создан стенд Unicorn/Cortex-M33 для выполнения отдельных функций.
Настоящая функция по смещению `0x12cc` выполнена с явной моделью одного
аппаратного регистра; результат проверен на 32 входных значениях.
Все 13 тестов прошли. Старт образа без модели оборудования останавливается
на первом неизвестном чтении `0x4008005c`.

Запуск из корня проекта: `run_band_emulator.bat`.
Инструкция, ограничения и примеры: [EMULATOR.md](EMULATOR.md).
Отчёты: `results/demo.json`, `results/startup.json`.

## Следующий этап выполнен: температура

Найдена вызывающая погодная функция по диагностической строке; выполнены

## Повторение анализа на ПК

Из корня рабочего проекта:

```powershell
python band_emulator/inspect_firmware.py
python band_emulator/list_romfs.py
python -m pip install --target band_emulator/python_deps -r band_emulator/requirements.txt
python band_emulator/disassemble_startup.py
```

Скрипты работают только с локальными файлами и не содержат команд прошивки.
Описание формата ROMFS: https://docs.kernel.org/filesystems/romfs.html
Результаты бинарного анализа получены из скачанного пакета, а не перенесены
из исследований Band 10.
