# Отладка Band 9 из браузера

Дважды открыть **`boot_band_emulator.bat`** или **`boot_band_browser.bat`**
в корне. Запускается Python-сервер и открывается браузер. Повторный запуск
подключается к уже работающей машине, сохраняя её состояние.

Это браузерный интерфейс к настоящему ARM-эмулятору. Unicorn и оригинальная
прошивка выполняются **на компьютере**, а браузер отправляет команды и
получает состояние. Установка Python на телефон не нужна. Компьютер и процесс
сервера должны оставаться включёнными; закрытие вкладки не останавливает CPU.

## Другие устройства

Вверху нажать **«Подключить устройство»**. Выбрать адрес домашней сети
(обычно `192.168.…`) и скопировать **полную ссылку с ключом** в браузер телефона.
Телефон должен быть в той же сети. `127.0.0.1` доступен только на компьютере.
Из другой сети требуется VPN до компьютера; публичный интернет-доступ не настроен.

Сервер слушает `0.0.0.0:8765`. Ключ создаётся заново при каждом запуске процесса,
передаётся во фрагменте ссылки и сохраняется в sessionStorage вкладки.
После открытия фрагмент убирается из адресной строки. Все HTTP API требуют
Bearer-ключ; статическая оболочка доступна без него. Ключ даёт управление
этой виртуальной машиной. Ссылки сохранены в `results/browser-session.json`.
HTTP предназначен для доверенной локальной сети/VPN, не для открытого Интернета.

Несколько браузеров видят **одну машину и общие снимки**. Команды всех клиентов
проходят через единственную очередь; CPU принадлежит одному рабочему потоку.
Сброс влияет на всех подключённых пользователей. Браузер обновляет состояние
примерно раз в 600 мс, в скрытой вкладке — реже. Последовательные версии
состояния не позволяют запоздавшему ответу откатить интерфейс назад.

## Управление

- **Запуск / Пауза / Шаг**. Шаг: 1, 100 или 10000 инструкций, с ограничением
  времени. Если пакет прервался по времени, фактически выполненное число видно
  в счётчике. Неизвестное оборудование останавливает машину.
- **Отладчик → Точки останова**: произвольный допустимый адрес или готовые
  точки AppBringUp, после АЦП, после регистрации разделов, начало Bluetooth.
  Крестик удаляет точку. Добавление ставит машину на паузу; далее нажать «Запуск».
- **Снимки**: до 8 именованных снимков в RAM сервера, включая CPU, SRAM/PSRAM,
  устройства и виртуальные входы. Восстановление ставит машину на паузу.
  Сброс машины и завершение сервера удаляют снимки; диск не используется.
- **Регистры**: r0–r12, sp, lr, pc. Изменение состояния после аппаратной ошибки
  не позволяет обойти остановку: сначала восстановить снимок или сбросить CPU.
- **Память**: чтение до 4096 байт, HEX/ASCII. Запись от 1 до 256 HEX-байт
  только в RAM/PSRAM. Образ прошивки и виртуальный заводской сектор защищены
  от записи. MMIO через редактор не выдаёт произвольные ответы.
- **Входы платы**: GPIO 0–79, АЦП 0–255. Значения и их смысл описаны в
  [BOOT.md](BOOT.md). Каждое изменение ставит исполнение на паузу.
- **Отчёт**: скачивание полного JSON с трассой, аппаратными заменами и
  ограничениями. Это диагностический отчёт, не файл восстанавливаемого снимка.

На главной вкладке показаны фактические задачи и этапы исполнения прошивки.
Изображение часов не подменяется макетом: дисплей пока не эмулируется.
Текущая аппаратная граница ядра — контроллер дисплея `0x40200000` (см. BOOT.md).

## Запуск из терминала

```powershell
python band_emulator/web_server.py --open
python band_emulator/web_server.py --host 127.0.0.1 --port 8766
.\boot_band_emulator.bat --desktop
.\boot_band_emulator.bat --cli --until storage
```

Первый вариант доступен в локальной сети. Второй — только с этого компьютера.
Остановить сервер из его терминала: Ctrl+C. Дополнительные Python-зависимости
для браузерного интерфейса не нужны: HTTP-сервер использует стандартную библиотеку.
API не предоставляет запуск команд, загрузку файлов или чтение произвольных
путей на компьютере. Пути статических файлов перечислены явно.

## Проверки

**95 тестов** прошли: `results/test-run-browser.txt`. Из них 8 новых проверок
реального HTTP: авторизация, Origin, два клиента, выполнение шагов,
снимки/восстановление, GPIO/АЦП, редактирование RAM и регистров, защита образа,
невалидные команды, запрет обхода терминальной ошибки и полный отчёт.

В браузере проверены исполнение прошивки до SPI, реальные четыре задачи,
чтение RAM по `0x200af50c` (ревизия4), сетевые ссылки и мобильная вёрстка.
При узком окне ширина содержимого не превышает ширину страницы.
HTTP проверен на `127.0.0.1` и локальном адресе `192.168.0.105` с этого ПК.
Физическое подключение с телефона пользователь отложил; оно не заявляется проверенным.

```powershell
python -m unittest discover -s band_emulator/tests -p test_web.py -v
python -m unittest discover -s band_emulator/tests -v
```
