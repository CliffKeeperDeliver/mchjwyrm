# Ядро эмулятора и отладчик

## Запуск

Из корня проекта:

```powershell
.\debug_band_emulator.bat
```

В память загружается исходный образ Band 9 Global 2.3.98; PC устанавливается
на стартовый участок `0x0c100010`. Инструкции выполняет Unicorn Cortex-M33.
Ввод `help` выводит команды. Для запуска не нужен телефон или браслет.

## Пошаговое исследование загрузки

Последний воспроизводимый опыт с IOMUX и таймерами:

```powershell
.\debug_band_emulator.bat --script band_emulator/scripts/startup-io.debug
```

Обе экспериментальные ревизии (13 / 14) проходят настройку выводов,
выбор источников в CMU и запускают оба таймера. Остановка — чтение
**AON BOOTMODE `0x40080038`** при PC **`0x0c1015fc`**.
Счётчики с исходного состояния — **85 925 / 85 926** инструкций.
Отчёты: `results/debug-startup-io-revision13.json`,
`results/debug-startup-io-revision14.json`, `results/debug-startup-io-restored.json`.

IOMUX хранит числовые маршруты 80 выводов и настройки подтяжек.
В отчёте `iomux_control.pins` видны результат и состояние каждого вывода.
Это модель конфигурации: электрические уровни, GPIO и подключённые устройства
не воспроизводятся. Начальные нули — допущение опыта, не считанные reset-значения.
Для регистра `0xac` сохраняются только наблюдаемые биты 10..13: их значение
в этой прошивке отличается от справочного SDK, поэтому назначение не выдумано.

Опция `timers on` моделирует канал 0 блоков `0x40084000` и `0x40003000`.
Поддерживается 32-битный свободный счёт вниз без делителя и включения IRQ.
Один допущенный шаг CPU даёт один входной тик; ошибка откатывает и этот тик.
Чтение регистров само по себе не сдвигает время. Пауза отладчика также не
меняет таймеры. Снимки сохраняют их счётчики и виртуальное время.
Физические частоты, разница медленного/быстрого генераторов, управление тактированием
через CMU, периодический режим, one-shot и доставка прерываний отсутствуют.
Неподдерживаемые режимы дают ошибку.

Интерактивный вариант:

```powershell
.\debug_band_emulator.bat --core --cache --aon-chip-id 0x000e0000 --ram-execution --iomux --timers
```

Затем `cmu on` и `run 100000 20000`; команды `iomux`, `timers` и `cmu`
показывают состояние. Вместо `cmu on` можно передать ключ запуска `--cmu`.
Ревизия 14 здесь — явно заданный вариант опыта, не определение ревизии браслета.
CMU пока хранит только наблюдаемые биты 10..11 регистра PERIPH_CLK;
модель не воспроизводит дерево частот, PLL и сбросы устройств.

Предыдущий опыт до первого обращения к IOMUX сохранён:

```powershell
.\debug_band_emulator.bat --script band_emulator/scripts/startup-ram.debug
```

Он запускает настоящий образ с двумя **экспериментальными** значениями
регистра CHIP_ID: `0x000d0000` и `0x000e0000`. Фактическая ревизия браслета
пока неизвестна; здесь проверяются обе ветки сравнения ревизии с 13.
Прошивка сама настраивает оба кэша, копирует **43 608 байт** из flash
в RAM и начинает исполнять перенесённый код через зеркало `0x00200000`.
Остановка — запись `0xffffffff` в **`0x40086008`** (IOMUX), PC `0x00260092`.
Счётчики — **83 984** и **83 985** инструкций соответственно. Полной загрузки нет.

Результаты: `results/debug-startup-revision13.json`,
`results/debug-startup-revision14.json`, `results/debug-startup-ram-restored.json`.
Последний отчёт проверяет возврат к исходному состоянию без новых моделей.

Для интерактивного запуска:

```powershell
.\debug_band_emulator.bat --core --cache --aon-chip-id 0x000e0000 --ram-execution
```

Затем `run 100000 20000` (до 100 тысяч инструкций, максимум 20 секунд).
Если сработал лимит времени, `run` продолжает с текущего места. `aon` показывает
экспериментальную идентификацию, `ram` — карту зеркала, `disasm` — код в RAM.
Не добавляйте `model 0x4008005c 0` вместе с AON: этим регистром уже управляет модель.

Ниже сохранён прежний пошаговый опыт с минимальным набором моделей.

```text
save power_on
step
step
regs
break 0x0c1012cc
run
disasm
delete 0x0c1012cc
run
```

`step` выполняет одну инструкцию, `step 10` — до десяти. `run` продолжает
до ошибки, точки останова, контролируемого возврата или лимита.
Все адреса отладчика — **адреса в эмулируемой памяти**, не смещения в файле.
Прибавляйте к файловому смещению базу `0x0c100000`.

Первая остановка прошивки — чтение `0x4008005c`. Можно явно добавить
экспериментальную модель этого регистра:

```text
model 0x4008005c 0
run
x 0x2005c000 64
save vectors
report
```

Так начальный участок заполняет в RAM таблицу из **94 слов** и достигает
записи адреса `0x2005c000` в **VTOR (`0xe000ed08`)**. Без включённой модели
системного блока эта запись останавливает эмулятор. Добавленная модель
первого регистра — только 32-битное хранилище, без аппаратных эффектов.

Чтобы продолжить с текущего места:

```text
core on
cache on
run
core
cache
```

Теперь прошивка проходит настройку VTOR, приоритетов исключений, CCR,
SHCSR, CPACR и включение первого кэша. Следующая остановка — чтение
**`0x40080000`** при PC **`0x0c10154a`**. Значение этого регистра ещё
не установлено, поэтому загрузка здесь останавливается.

Модель SCB/NVIC поддерживает конфигурацию, приоритеты, установку/сброс
разрешения и ожидания IRQ. Она **не доставляет прерывания**: если IRQ
ожидает и разрешён, исполнение останавливается с
`interrupt_delivery_required` даже при маскировании IRQ в CPU.
Таймеры, аппаратные ловушки, FPU-доступ и TrustZone не моделируются.
Модель кэша поддерживает наблюдаемые управляющие операции, считая память
сразу когерентной; строки кэша и задержки не моделируются.
[Основания и допущения моделей](references/README.md).

Без пауз до первого неизвестного регистра — 5 допущенных инструкций.
При заранее заданной модели этого регистра до VTOR — 683; с `core on` —
722 до первого обращения к кэшу; с `core on` и `cache on` — 743 до
следующего неизвестного регистра. При остановке
и повторе ошибочной инструкции счётчик будет больше: он учитывает попытки,
включая повтор. Это счётчик инструкций, не число тактов.

Готовый сценарий:

```powershell
.\debug_band_emulator.bat --script band_emulator/scripts/startup.debug
```

Сценарий с новыми моделями (включает их сам):

```powershell
.\debug_band_emulator.bat --script band_emulator/scripts/startup-core.debug
```

Он сохраняет `results/debug-startup-core.json` и отчёт восстановления
исходного состояния. После запуска доступно интерактивное исследование
через `.\debug_band_emulator.bat --core --cache`; затем введите
`model 0x4008005c 0` и `run`.

Сценарий сохраняет три отчёта: первая аппаратная зависимость, заполненная
таблица векторов и состояние после восстановления исходной точки.
Скрипт исполняет только команды отладчика; Python/eval и shell в нём нет.
Код возврата 0 означает успешное выполнение команд, **не загрузку ОС**:
скрипт намеренно может останавливаться на ошибке гостевой прошивки.

## Возможности

| Команда | Действие |
| --- | --- |
| `step [N]`, `run [N] [TIMEOUT_MS]` | Шаги / продолжение с лимитами инструкций и времени |
| `break ADDRESS`, `delete ADDRESS` | Добавить / удалить точку останова |
| `regs` | Обычные и системные регистры CPU |
| `set r0 VALUE`, `set pc ADDRESS` | Изменить регистр или точку выполнения |
| `x ADDRESS SIZE` | Прочитать RAM или образ, максимум 4096 байт |
| `write32 ADDRESS VALUE` | Изменить слово в RAM |
| `disasm [ADDRESS] [COUNT]` | Дизассемблировать до 64 инструкций |
| `model ADDRESS VALUE` | Явно заменить один MMIO-регистр обычным хранилищем |
| `core on`, `core` | Включить / показать частичную модель SCB/NVIC |
| `cache on`, `cache` | Включить / показать модель управления кэшем |
| `aon CHIP_ID`, `aon` | Включить / показать AON с явно заданной экспериментальной идентификацией |
| `ram on`, `ram` | Включить / показать зеркало RAM для исполнения |
| `iomux on`, `iomux` | Включить / показать конфигурацию выводов и подтяжек |
| `timers on`, `timers` | Включить / показать таймеры с виртуальным входным тактом |
| `cmu on`, `cmu` | Включить / показать выбор источников таймеров в CMU |
| `irq N` | Установить ожидание внешнего IRQ; доставка не реализована |
| `devices`, `maps`, `trace`, `status` | Модели регистров, карта памяти, трасса, состояние |
| `save NAME`, `restore NAME` | Сохранить / восстановить CPU, RAM и MMIO |
| `report [PATH]` | Записать JSON-отчёт |
| `quit` | Завершить сеанс |

При продолжении с точки останова её текущая инструкция выполняется один
раз. Повторный заход на тот же адрес снова останавливает исполнение.

Сохраняется до 8 точек **в памяти текущего процесса**. Это полный контекст
Unicorn, RAM и наличие её исполняемого зеркала, смоделированные регистры,
состояние SCB/NVIC, кэшей, AON, IOMUX, CMU и таймеров,
карта MMIO и журнал/счётчики.
Точки останова относятся к настройке отладчика и при восстановлении
не меняются. После выхода точки сохранения исчезают; JSON-отчёт — материал
для анализа, не файл состояния, который можно загрузить обратно.

## Ошибки и повтор инструкции

Перед каждой инструкцией сохраняется контекст CPU. Для её записей в RAM
ведётся журнал предыдущих значений. При неизвестном адресе, регистре или
неподдерживаемом исключении CPU, RAM и состояние моделей периферии возвращаются
к состоянию **до этой инструкции**. Ранее выполненные инструкции сохраняются.

Поэтому после добавления модели можно повторить ошибочную инструкцию,
а не начинать всё заново. В отчёте присутствует
`instruction_state_rolled_back: true`. Трасса и счётчик сохраняют сведения
о неудачной попытке. Откат относится к текущей синхронной модели; внешних
устройств, фонового времени и необратимых эффектов здесь нет. Виртуальные
таймеры меняются только синхронно с гостевыми инструкциями и тоже откатываются.

## Память

- Основной образ: `0x0c100000`, чтение/исполнение.
- Зеркало для чтения: `0x2c100000`. Его наличие выведено из указателей на
  строки в прошивке. Байты совпадают с основным образом; оба неизменяемы.
- RAM: `0x20000000`–`0x2015ffff`, чтение/запись, исходно нулевая.
- При `ram on`: зеркало `0x00200000`–`0x0035ffff`, чтение/исполнение.
  Оба адреса используют один буфер: копирование прошивкой и изменения
  через `write32` сразу видны через зеркало. Запись через зеркало запрещена
  ограничением стенда. Данные RAM по-прежнему нельзя исполнять по `0x20000000`.
  Изменения кода сбрасывают соответствующие переводы Unicorn перед продолжением.
  Шаги, точки останова, дизассемблер и откат ошибок работают и в RAM.
- Начальный SP: `0x2015fe80`.
- Адрес возврата стенда: `0x10000000`.
- MMIO существует только после явного добавления модели. Соседние адреса
  той же страницы автоматически не получают нулевое значение.

Полная карта чипа ещё не восстановлена. SCB/NVIC и кэш реализованы только
частично. AON поддерживает идентификацию и наблюдаемые биты RAM_CFG/CLK_OUT.
Таймеры поддерживают только описанный выше экспериментальный режим.
Не реализованы доставка прерываний, физическое тактирование, ROM-подпрограммы,
внешняя память и устройства браслета. Полной загрузки NuttX
пока нет. Выбор CPU M33 не превращает Unicorn в модель всего BES SoC.

## Проверки

```powershell
python -m unittest discover -s band_emulator/tests -v
```

67 тестов прошли: пошаговое продолжение, точки останова, восстановление
CPU/RAM/MMIO и моделей устройств, повтор неизвестного чтения, откат
частичной многословной записи в RAM и периферию, защита образа, семантика
NVIC и настоящий старт до следующего неизвестного регистра. Отдельно
вызвана настоящая функция включения обоих кэшей при исходно сброшенном
и уже установленном бите включения.
Добавлены проверки когерентного зеркала RAM, изменения уже исполненного
кода гостевой программой, защиты адресных представлений, отката записи,
снимков с включением/отключением зеркала и двух веток ревизии настоящего старта.

Проверены поля всех 80 выводов, виртуальный ход таймеров, цикл ожидания,
переход счётчика через ноль, очистка статуса, откат времени при ошибке,
снимки устройств, откат частичной записи в CMU и обе ветки старта до BOOTMODE.

Дальнейшая работа по ядру: семантика BOOTMODE `0x40080038`, связь таймеров
с физическим тактированием и последующие зависимости, затем доставка IRQ.
